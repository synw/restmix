# Restmix

## Mission
A lightweight, TypeScript-friendly requests manager for REST APIs that wraps `fetch`, handles response body parsing, and delivers typed data through a composable `useApi()`.

## Repositories

| Repo | Path | Purpose |
|------|------|---------|
| `restmix` | `./` | Library source (`src/`), tests (`test/` + express test server), rollup build (`dist/`), and the Vite/Vue documentation site (`docsite/`). |

## Quick Start for AI Agents

1. Read `.agents/documentation/decision-tree.md` — the router: it tells you exactly which doc or source file your task needs.
2. Most tasks end here: go straight to the listed source files. Do not load every doc.
3. Before changing behavior, architecture, or tests, ground the task in design intent: run `lat search "<task>"` and read the returned sections (see § Code Search).
4. Load additional docs only when needed:
   - `.agents/documentation/project-overview.md` — only for conceptual context
   - `.agents/documentation/project-nav.md` — only for deep reference (conventions, snippets, maps)
5. Read `.agents/documentation/codebase-summary.md` for the machine-readable technical summary of this module.

## Code Search (lat)

`lat` searches the project knowledge graph in `lat.md/`: cross-linked markdown describing design intent, API contracts, and test specs, anchored to source code via `// @lat:` refs.

- `lat search "<task>"` — semantic search for sections relevant to your task (requires `LAT_LLM_KEY`; `sk-...` or `vck_...` prefixes)
- `lat locate "<section name>"` — direct lookup by exact/fuzzy section id; use when no key is configured
- `lat section <id>` — show a section with its links and refs
- `lat refs <id>` — find what references a section
- Run `lat --help` when in doubt.

Post-task (required): if you added or changed meaningful behavior, architecture, or tests → update the relevant `lat.md/` file, then run `lat check` until all validations pass.

Do not edit `lat.md/lat.md` — it is generated by the lat tooling and may be replaced by a later `lat init`.
